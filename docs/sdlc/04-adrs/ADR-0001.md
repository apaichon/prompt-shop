# ADR: ADK Live and Laya behind a Go application gateway

## Status

Proposed, revised for the user's explicit Gemini Live 3.8 voice-to-voice, Google ADK and Laya intent-classification requirements. This supersedes this draft's earlier separate transcription/synthesis proposal. It is not an implementation approval or permission to provision cloud resources; [DES-0001](../03-designs/DES-0001.md) remains unsigned.

## Context

Planning starts 13 October 2026; GCP deployment is due 16 October and submission 18 October, Bangkok time. Required stack is Svelte, Go Fiber, PostgreSQL, Docker and GCP, with selective reuse of Monti Jarvis and customer/backoffice in one portal. English is mandatory; Thai, Chinese and Japanese are time-permitting. User explicitly requires Gemini Live 3.8 native audio dialogue with ADK orchestration and Laya intent classification; a recording/STT/text/TTS chain does not satisfy that requirement. Catalog/database expansion remains required; vector retrieval follows the working concept.

## Decision

1. Serve a static SvelteKit shopper/backoffice portal and Go Fiber public gateway in one Cloud Run revision with private Python ADK and Laya containers, backed by Cloud SQL. Keep protected catalog create/edit/publish/archive and maintainer session/CSRF contracts unchanged.
2. Use Python ADK `Runner.run_live` with a fresh `LiveRequestQueue` per connection; the [official live configuration](https://adk.dev/live/configuration/) distinguishes this from `run_async`/SSE. No raw Gemini bypass or assumed Go ADK live support. Pin `gemini-3.8-live` with native audio response and bidirectional streaming. Enable input/output transcription for captions. Follow the [official model migration requirements](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-live): no thinking configuration, no removed affective option, no disabled proactive audio, and explicit `BLOCKING` catalog functions. Structured output is not a supported substitute for server DTO validation.
3. Stream browser PCM16LE mono16kHz through the backend WebSocket and play returned PCM16LE mono24kHz. Process all provider event parts, not a single selected branch; flush playback and cancel stale turn work on interruption. These audio formats and multipart events follow the [Live capabilities guide](https://ai.google.dev/gemini-api/docs/live-api/capabilities). Spoken clarification and selection are supported; clicks are optional.
4. Use `classify_intent`, `search_catalog` and `get_product_route` as the only tools. ADK calls the private Laya classifier once before catalog actions; catalog callbacks target fixed authenticated loopback Go routes, not caller-chosen URLs. Candidate membership, publication state, map versions and walkable paths are checked in Go/PostgreSQL. Render factual cards directly from tool results. System instructions and blocking tools ground the spoken response, but do not mathematically prevent generated audio from inventing facts; zero fabricated location is a release test, not a promise derived from prompts.
5. Use a same-origin POST to issue a 30-second single-use secure HttpOnly cookie ticket, atomically consumed by WSS upgrade. Keep provider API key in Secret Manager and out of browser/URL/logs. Cap session at five minutes from ready, idle at one minute and setup at 30 seconds; fresh reconnect requires a new ticket and conversation. Cloud Run timeout is 360 seconds because [WebSockets are still subject to request timeout](https://docs.cloud.google.com/run/docs/triggering/websockets).
6. Adapt only relevant Monti microphone/audio worklet, `montiVoice`, live-relay/tool/interrupt and UI/catalog patterns. Preserve source license and provenance. Rewrite net/http-specific integration for configured Fiber, migrate older Gemini 2.5 assumptions, and test actual 3.8 model behavior. Do not import the whole Store, commerce stack, Redis/MinIO/ClickHouse, secrets or customer data.
7. Add a mandatory private Laya service using the English `convaiinnovations/laya` checkpoint, pinned/preloaded CPU weights and a fixed four-label intent schema. Its [installation and model guidance](https://github.com/NandhaKishorM/laya#installation-details) informs the wrapper; repository benchmark numbers are not our deployment measurements. Classification is advisory and may abstain; it never grants authorization or supplies locations. Keep deterministic alias search and operator import, with pgvector deferred. Typed search remains recoverable during Live failure, but cannot substitute for required voice acceptance. A different provider/model needs explicit user approval.


8. Keep all ADK sessions/events transient: in-memory session service, `save_live_blob=false`, no persistent artifact service and explicit queue/task/provider/session cleanup on every exit. ADK queues need an application bound; default unbounded behavior is documented in [ADK sessions](https://adk.dev/live/sessions/). SDK qualification must prove the outgoing 3.8 tool declarations remain `BLOCKING`, not merely assume sequential function implementation does so.
9. Adapt Monti's interactive assistant panel, mobile drawer, product highlight and action-card patterns into candidate selection/map controls only. UI actions derive from Go-verified session/turn-tagged events; old events after Stop or interruption are discarded. No model-generated arbitrary UI commands, automatic microphone start, cart or checkout.

## Alternatives considered

| Option | Decision |
|---|---|
| Separate STT -> text search -> TTS | Rejected for this scope: user requires native Gemini Live 3.8 voice-to-voice |
| Direct browser/Go-to-Gemini bypass | Rejected for this scope: user requires ADK; Go retains admission and catalog authority while Python owns the Live runner |
| Go ADK-only runtime | Not selected: current documented live starters/configuration support Python/Java; do not infer Go live capability from SSE support |
| Inline Laya inference on ADK event loop | Rejected: CPU inference must not stall native audio; use a bounded private worker service |
| Copy Monti's complete live/commerce backend | Rejected; unrelated infrastructure and old-model assumptions increase delivery risk |
| Separate frontend hosting/API | Deferred; one origin/deploy simplifies ticket cookies, microphone HTTPS and integration |
| Vector-first retrieval or model-authored route | Deferred/rejected as authority: semantic similarity and language generation cannot establish a truthful shelf/path |

## Consequences

A natural spoken request, clarification, choice and directions can happen in one session with visible captions and a verified map. Reuse can accelerate audio plumbing, but copied source is not proof of target-model or deployment compatibility. Day-one evidence must include microphone input, audible 3.8 response, a real tool round trip and interruption; failure is raised as a blocker rather than covered by another provider.

Long-lived connections add cancellation, queue limits, timeout, reconnect and cost risks. Tickets persist in PostgreSQL so admission works across replicas; transient conversation state remains with the owning gateway/ADK connection and is deliberately reset on reconnect. ADK may hold transcript/tool events in memory; explicitly delete them at session end, while durable audio/transcript persistence remains disabled. Confirm provider account/data terms, quota and budget separately; no universal zero-retention or global spending-cap claim.

Spoken grounding requires testing beyond correct JSON. Model speech can diverge from tool records even when rendered cards are correct. Ambiguous turns need clarification and current-candidate validation; interruption must not leak old audio or directions. Release targets are p95 ≤5 seconds to first actionable audio and ≤8 seconds to verified card from user speech end over 30 warm turns; measure setup/cold start separately. These are proposed targets, not measured outcomes.

Cloud SQL and active WebSockets have costs; bounded sessions/scaling and provider quotas reduce exposure without creating a hard spending cap. Limited backoffice remains a write/security surface and needs its existing auth, CSRF, state/version and publish-to-shopper tests. Protect the deadline by deferring extra languages, recipes and embeddings before weakening required ADK/Laya/native Live voice, grounded locations or the GCP acceptance gate. No automatic removal of a required component.

Three containers add startup, private authentication and resource costs. Proposed per-instance allocations total 4 vCPU/5 GiB (Go 1/512 MiB, ADK 1/512 MiB, Laya 2/4 GiB); these require measured qualification and budget approval. Laya has one worker/queue of four, ≤200 ms queue wait and 1,200 ms total deadline. Inference failure abstains safely, but cannot count as successful required integration. Freeze thresholds before a 40-case balanced English holdout and target ≥36 correct, counting normal abstentions/errors as misses. Report confusion/coverage; do not treat confidence as calibrated certainty. Actual package/model pins, three-service startup, cleanup, tool behavior and end-to-end latency remain pre-release evidence requirements.

from SSE is historical, not a current claim that Go lacks Live. The existing Python

## TASK-0014 tool orchestration amendment

For the user-authorized local latency improvement, model-visible tools become
`begin_conversation`, `find_product` and `select_product`, all BLOCKING. The three
original primitive operations remain private host adapters: real Laya → current
Go ACK → search → unique route execute within one lookup call. Ambiguous choices
still require a later shopper turn and Go validation. This replaces decision 4's
model-facing names without changing ADK, Laya, native audio or Go authority. See
[DES-0001](../03-designs/DES-0001.md#task-0014-model-facing-tool-amendment--16-october-2026)
and [measured evidence](../07-tests/evidence/TASK-0014/README.md). No language/runtime
rewrite or unmeasured Duangjai latency equivalence is claimed.


## TASK-0020 summary flow amendment — 17 October 2026

User-authorized local conversation summaries add model-visible BLOCKING
summarize_items(text). It composes the existing real Laya classification/Go ACK
with one new capability-protected private get_conversation_summary(args={}) call.
Go owns the bounded session facts and emits the validated summary snapshot to the
browser; model text supplies no products or locations. No runtime/model change,
new database, cross-session memory or free-form factual UI channel is introduced.
A browser completion/playout/quiet timer requests one conversational offer through
the same authenticated native connection. Summary/decline cannot autonomously
rearm it; a new catalog lookup is required. Full acceptance gates remain unchanged.
