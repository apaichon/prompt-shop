# ADR: Choose voice tools with Gemini Embedding 2 cosine labels

## Status

Approved for implementation behind `INTENT_BACKEND=embedding`. ADR-0001 and REQ-0006 stay the rule for the Laya path and the 18 October submission.

## Context

The voice runtime needs one label before it looks up a product, repeats a route, or summarizes a session. Laya is an 843 MB checkpoint. The reviewed host run held about 1.9 GiB, used 2 CPU threads, took about 8.2 seconds to become ready, and scored a warm p95 of about 267 ms. It accepted 19 of 40 frozen sentences.

`gemini-embedding-2` is the stable Gemini Developer API embedding model checked on 17 October 2026. It embeds text. It does not call tools. The demo already uses a Developer API key. The model has no `task_type` parameter, so the same classification prefix must be applied to the shopper sentence and to every prototype. Its vectors cannot be mixed with `gemini-embedding-001`.

Go already returns aisle and shelf. The label must not become a location.

## Decision

1. Keep Laya as the default `classify_intent` backend. Select the embedding router only when `INTENT_BACKEND=embedding`.
2. Embed finished English text with `gemini-embedding-2` at 768 dimensions. Prefix every string, including prototypes, with `task: classification | query: `.
3. Pick the label with the highest cosine similarity against a frozen prototype list. Confidence is that cosine clamped to the range 0 through 1. Margin is the gap to the next label. Abstain below 0.70 confidence or below 0.15 margin.
4. Apply session state before similarity. `select_item` is eligible only when the session has current results. `repeat_directions` is eligible only when the session has a current route.
5. When the embedding revision is in use, the label allows the tool. `find_item` may search and then route a unique match from that search. `select_item` may route only a product already in the current results. `repeat_directions` may repeat only the stored route. `summarize` may read the conversation summary. `out_of_scope` and abstain may speak and may not call catalog, route, or summary tools.
6. Return the existing intent-v1 fields. The embedding revision may use the additional success label `summarize`. Do not send that result through the Laya `result()` checker, which stays pinned to the Laya revision and the original four labels.
7. Log latency, status, and token count only. Do not log the shopper sentence, the prototype text, the API key, or the embedding values.
8. Leave REQ-0006, TEST-0002, and TEST-0012 on the Laya path. Do not remove the Laya process in this decision.

## Consequences

- A classified turn spends one remote embedding request and uses the existing Gemini key. Price was not calculated here and must be confirmed before a runtime cutover.
- The first uncached prototype embed can miss the 1.2 second classification deadline. Callers warm the prototype cache before traffic when the flag is on.
- Similarity can abstain on a short selection phrase when no results exist. That is safer than starting a new search for "the second one".
- 768 dimensions are the low-resource choice, not a measured quality result. A later gate may re-embed the same prototypes at 1536 and rerun the same frozen sentences.
- Rollback is unsetting `INTENT_BACKEND` so the process returns to Laya. No schema migration and no portal change.

## Alternatives considered

| Option | Why it was not chosen |
|---|---|
| Keep Laya as the only router | It is the wrong size of model for four or five labels and it missed the 36-of-40 bar. |
| Let Gemini Live pick the tool and skip a router | The live model already picks a flow, and a short phrase such as "the second one" can start a new search. The roadmap asks for the label to allow the tool. |
| Embed the microphone audio | The turn already has text. Audio embeddings add cost and a second model path. |
| Use the embedding as product search | Go and the catalog remain the authority for products and shelves. |
