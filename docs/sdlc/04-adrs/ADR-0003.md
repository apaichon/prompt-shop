# Go ADK compatibility before port

The user authorized starting the Go migration. Monti already relies on manual
activity boundaries, ordered authorization metadata and suppression of stale
audio. Existence of a bidirectional SDK sample does not prove these contracts.

Use a separate module pinned to ADK v2.6.0 and GenAI v1.74.0 for wire tests and
an opt-in real-model probe. Keep the Python runtime active until this gate passes
and the full port has separate parity, resource and rollback evidence. A future
single-process Go deployment is not decided by this spike.

This limits dependency/build impact and makes unsupported SDK fields visible
before application code is migrated. It can produce a no-go result. Do not call
fixtures real-provider evidence or replace ADK with a direct Live client to make
the gate appear green. No runtime release or cloud action is approved here.

The wire and race probes found three SDK defects. The compatibility amendment in
DES-0004 permits explicit minimal patches in checksum-verified, ignored SDK
copies. Keep all three patches in `agent-go/compat/`, identify them in native reports
and rerun the same wire/race/provider checks. This is a traceable experiment,
not a silent change to upstream modules or a qualification of the stock SDK.
