# Required Gemini Live English conversation and recovery

Acceptance procedures are specified below; current partial execution and blockers are recorded in the TASK-0006 evidence section. Required model is `gemini-3.8-live`, executed through mandatory ADK `Runner.run_live()` with actual Laya `classify_intent` participating in every completed semantic native-voice turn, including out_of_scope and repeat requests. Disabled Laya, mocks, heuristic replacement or always-abstain behavior cannot pass this integrated gate. A raw Gemini client bypassing ADK, a different model, typed-only success or separate transcription/synthesis pipeline cannot pass the voice gate. Model access failure is a blocker, never grounds for an unreported substitution.

## Setup
- Use TEST-0001's frozen 30 prompts/expected IDs and the declared Chrome demo device/microphone/network, release revision and catalog/map versions. Start voice explicitly; automatic VAD delimits conversational turns until Stop. Input/output transcript events are displayed as provisional side-channel captions; they never trigger a separate transcription-to-search pipeline. Missing caption events never authorize invented captions or locations.
- Confirm ADK runtime invocation and pinned package identity together with model identity in the setup request and provider connection evidence; request AUDIO responses. The [official model page](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-live) identifies this model and native Live support. Apply the reviewed settings in DES-0001; never rely on a UI label as model evidence.
- Session contract: POST `/api/voice/sessions` with `{language:"en-US"}` returns session metadata and a single-use 30-second HttpOnly ticket cookie; WSS `/ws/voice` checks exact Origin and consumes the ticket atomically. Input is PCM16LE mono 16 kHz (100 ms/3,200-byte chunks, maximum 6,400); output is PCM16LE mono 24 kHz. Validate actual sample rate/channel count and intelligible playback.
- Limits: setup 30 seconds; app session 300 seconds from ready; idle 60 seconds; Cloud Run request 360 seconds; four live sessions/instance, two instances maximum. Benchmark across explicit fresh sessions as needed; do not extend lifetime to fit 30 turns. Use the approved three-container Go gateway/Python ADK/Laya runtime with private authenticated bridge; TEST-0008 supplies boundary and lifecycle evidence. Warm each service/session separately and keep setup/cold-start times out of the turn percentile.
- Prepare isolated protocol/provider/tool failure injection, unknown/adversarial queries, ambiguous milk, a cancelled tool call and stale generation results. Use synthetic benchmark utterances; application logs retain no raw audio, queries, transcript content, cookies or secrets. QA records IDs, event timings and factual comparison verdicts; optional synthetic output transcripts for audit stay in restricted QA evidence.

## Steps
1. Start voice and speak each frozen English request once. Verify native audio input reaches the declared live model, the native model calls ADK `classify_intent` on the utterance text and actual pinned Laya inference returns its advisory typed result before `search_catalog` executes read-only lookup, and server-verified result events produce candidate cards and the intended interactive highlight. Model-proposed HTML, arbitrary UI actions or unchecked prose cannot create or mutate shopping UI. Listen to the complete spoken answer and compare every item/aisle/shelf assertion with corresponding tool facts; do not score only the transcript or UI.
2. For ambiguous milk, receive spoken clarification and at most three stored candidates, then speak a selection and verify real Laya classification on that follow-up turn. Verify `get_product_route` receives a current `search_id` and candidate `product_id`; spoken selection or explicit click confirms before route. Compare the ensuing voice answer, selected-card highlight and map with tool results. Complete the same selection with keyboard/click and independent typed search; changes must stay synchronized without stale events taking back focus or selection. Repeat with a correction to a different item; displayed transcripts are informational. Typed search remains a separate recovery path.
3. For each of 30 warm supported initial turns, timestamp the last voiced user sample using the client capture clock with QA/VAD annotation, the first audible sample of an actionable grounded answer or clarification, and the first visible verified candidate card. A filler such as “let me check” does not count. Measure from user speech end, not server tool invocation/transcript arrival. Separately time spoken-selection/clarification completion to route response; never mix that interval into the initial-turn series.
4. Interrupt a playing answer with a new spoken request. Verify barge-in flushes all queued old audio, stops the old generation, and ignores late audio/tool/card events from cancelled turns. Require matching session_id, turn_id and generation_id for updates; events arriving after Stop must never restore listening, audio or UI selection. Inject events containing multiple parts plus control/tool/transcript fields; all supported parts must be processed without an `else-if` branch dropping data. Reordered, duplicate, cancelled and timed-out tool results cannot mutate the current map or revive audio.
5. Speak unknown/adversarial requests from TEST-0001, including invented aisle instructions. Audit both audible assertions and UI against read-only tool facts. Inject a tool timeout/unavailable database separately: the assistant must say it cannot check right now, not falsely claim the item is absent. Tool failures never become empty-success/not-found results.
6. Deny/revoke microphone permission, disable audio capture, disconnect the socket, exhaust quota, expire the ticket/session and reach the idle limit. Verify clear states, stopped capture/playback, explicit Restart voice/reconnect and working typed recovery without reload. A fresh session must not replay old audio, execute stale tool results or silently claim conversation continuity. Stop always closes capture/session, closes the ADK queue and removes transient ADK conversation history; output failure preserves verified cards.
7. Make Laya unavailable, slow, overloaded and malformed in turn; require typed abstention and visible clarification/typed recovery without blocking PCM or barge-in. No disabled/abstaining failure run can count as successful required classification. Record real-checkpoint invocation and returned model_revision without logging raw text. Inspect session admission/origin enforcement, overlarge/malformed PCM rejection and bounded tool timeout against DES-0001. Measure one cold start/setup separately. Verify no raw audio or transcript bodies appear in app/proxy logs and no provider credentials reach the browser.

## Expected and pass/fail evidence
- Thirty normal native English turns complete; at least 27/30 expected products appear in the first three cards. For each timing series use nearest-rank p95: sorted sample 29 of 30. First actionable audible response p95 ≤5 seconds; verified candidate card p95 ≤8 seconds after utterance end. Typed lookup and explicit selection-to-route targets are ≤2 seconds in their separate 30-trial suites.
- Retain all normal failures, timeouts, retries and missing replies as failures, with no successful rerun substitution or typed-response substitution. Publish completion, correctness and latency separately. Consent/failure-injection suites and session setup/cold start are reported separately, never retrospective exclusions.
- Zero invented location assertions in voice or UI, including pre-tool speech. Preserve comparison records tying session/turn/tool IDs to authoritative facts and auditor verdicts. Incorrect speech fails even when the displayed card is correct.
- Evidence includes actual ADK runtime/package and exact model/configuration identity, PCM format checks, frozen fixture hash, per-turn timestamps, p95 calculation, tool grounding audit, barge-in/cancellation verdicts and recovery matrix. No voice success is claimed until the actual required model passes.

## Optional language smoke
English is mandatory. Thai, Mandarin Chinese and Japanese remain optional in that order. For each offered locale, freeze three known-item prompts, one ambiguity/selection exchange and one unknown request; verify native audio conversation, correct read-only tool facts, voice/card/map consistency and recovery. Disabled optional locales do not fail English acceptance; a failing offered locale must be disabled or fixed. Their results never join the English denominator.
