## Steps
1. On the 16 October release candidate, open HTTPS, exercise /healthz and /readyz, and record revision plus actual ADK `Runner.run_live()` runtime/package identity, pinned Laya checkpoint/model_revision and provider setup identity `gemini-3.8-live`. Start voice: native bidirectional PCM → spoken item request → actual Laya classify_intent → read-only catalog tool → audible grounded reply plus verified cards → spoken clarification/selection → route tool → voice and walkable map. Verify WSS ticket/Origin enforcement and true model identity, not a UI label. Repeat on the normal URL after promotion. Typed-only, alternate-model or separate transcription/synthesis flows cannot pass this release smoke. Required-model, Laya classifier or ADK-runtime unavailability blocks voice acceptance.
2. Confirm the acceptance results for TEST-0001–0003, TEST-0005 and TEST-0012 correspond to the final deployed revision or assess and rerun affected gates after any change. Complete a same-origin backoffice smoke: maintainer signs in, drafts/publishes one designated test product, shopper finds its stored shelf, maintainer logs out and direct write is denied. Use a separate product so the frozen benchmark is unchanged. Run 30 warm native English conversation turns (can share the exact TEST-0002 run), 30 warm typed queries from submit to visible candidates, and 30 warm selections from confirm to visible route. Compute p95 as the 29th sorted value in each 30-sample set. Save complete raw samples; failures remain failures. Separately exercise five simultaneous Live sessions plus typed/admin requests to check pool/provider limits and recovery; publish this load result separately from the baseline timing set.
3. Verify the Live setup30s, app session300s-from-ready, idle60s and outer Cloud Run360s limits; require explicit restart after disconnect/expiry and stop queued audio/capture. Run a deliberate cold-start session separately and record observed instance state, startup delay and end-to-end timings. Run denied-consent/unsupported-microphone flows separately. Do not combine them with warm samples or silently relabel failed normal voice attempts as consent errors. Record network/provider conditions and concurrent user count; this demo benchmark is not a load-capacity claim.
4. Record catalog row count, fixture checksum and one imported product ID. Restart the container or replace its revision, reconnect, verify health/readiness, confirm the same catalog/imported product remains and repeat lookup. Evidence must show persistence in PostgreSQL rather than ephemeral container files.
5. Inspect served JavaScript/configuration and representative app logs for credential/connection-secret leakage, raw audio or transcript content. Use controlled synthetic requests and redact credentials from QA evidence. Verify actual ADK run_live execution, the private authenticated Go↔ADK/tool bridge boundary, transient session cleanup, and server-only provider credentials/calls, all application/proxy logs exclude raw audio/transcripts, and no raw-audio retention. Audit actual audible location assertions as well as UI against current tool facts; exercise interruption and stale-result handling from TEST-0002. Readiness failure must not expose connection material.
6. With DevOps supervising the approved rehearsal, direct test traffic to the failing revision, start a timer at rollback initiation, follow the runbook to restore the known good revision, and repeat HTTPS/readiness plus the genuine English voice-to-route smoke. Gracefully end sockets remaining on the old revision with a restart notice and verify fresh sessions reach the restored revision. Record traffic/revision evidence and elapsed recovery time. Target is ≤15 minutes; a successful command without restored flow does not pass.
7. If Thai, Mandarin Chinese or Japanese is offered, attach the per-locale smoke results specified in TEST-0002; otherwise label the locale not offered. Disable a failing optional locale or fix it; do not fail the English-only release for disabled stretch work. Recipes/vector work have no required gate in this MVP.
