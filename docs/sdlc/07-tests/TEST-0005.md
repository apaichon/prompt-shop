# Test: Single portal and protected catalog maintenance

Planning specification only. The intended implementation selectively reuses reviewed `monti-jarvis` references; copied references are not an integrated or tested MVP. No test has been executed and the source repository must not be changed by this work.

## Setup
- One SvelteKit portal exposes shopper `/` and maintainer `/backoffice` on the same HTTPS hostname. Prepare an anonymous shopper, authorized maintainer, invalid credentials, expired session and logged-out session. Use isolated demo credentials; never copy source-project accounts or secrets. The curated source snapshot exists under references/monti-jarvis; this does not establish that the portal runs.
- Freeze the catalog/map fixtures from TEST-0001. Record original product version, aliases, draft/published/archived state and shelf; prepare two browser sessions editing the same product version and one new product with a valid existing shelf.
- Use DES-0001's proposed eight-hour absolute server session: `__Host-maintainer` cookie with Secure, HttpOnly, SameSite=Strict, Path=/ and no Domain attribute. Writes require the exact configured HTTPS Origin and session-matching `X-CSRF-Token`; optimistic edits pass `expected_version`.
- Retain a selected-copy manifest containing source revision, selected path, source/copy hashes, license/attribution disposition and excluded sensitive files. Checking the manifest during planning is not a successful MVP test run.

### Contract requests exercised

| Method and route | Fixture request / expected success |
|---|---|
| POST /api/backoffice/session | `{password}` → 200 expiry/CSRF plus cookie |
| GET /api/backoffice/session | Valid cookie → 200 expiry/CSRF |
| DELETE /api/backoffice/session | Valid cookie, Origin and CSRF → 204 revoked/cleared |
| GET /api/backoffice/products?q=&state=&cursor= | Valid cookie → filtered items, at most 50 per page |
| GET /api/backoffice/shelves | Valid cookie → existing shelf choices |
| POST /api/backoffice/products | `{id,name,category,shelf_id,aliases}` → 201 draft/version 1 |
| PUT /api/backoffice/products/{id} | Content plus current `expected_version` → 200 updated draft |
| POST /api/backoffice/products/{id}/publish | Current `expected_version` → 200 published |
| POST /api/backoffice/products/{id}/archive | Current `expected_version` → 200 archived |

Apply missing/invalid/expired auth to every protected row and CSRF/Origin failures to every mutation; login requires Origin without an existing session. Duplicate creation and stale version return 409; stale version specifically uses `VERSION_CONFLICT`.

## Steps
1. Visit `/` anonymously and perform search → selection → route with no account. Navigate to `/backoffice` on the same hostname; verify login is required and login preserves intended destination. Verify page refresh/deep links and keyboard navigation work on both surfaces.
2. Call every catalog mutation endpoint directly as anonymous, invalid-session and expired-session clients. Expect 401 `AUTH_REQUIRED` with no database changes; admin product/shelf reads also require auth. Repeat after explicit logout, including replay of the old cookie. Verify the eight-hour absolute expiry through a controlled clock/session fixture and prove normal activity does not extend it. Hiding a button is insufficient.
3. Log in as the maintainer. Verify cookie attributes above and that credentials/cookie values do not enter browser bundles or logs. Submit a write with a missing/invalid CSRF token and an untrusted Origin; both must return 403 `FORBIDDEN` without mutation. A valid same-origin request with valid session/CSRF succeeds. Verify login validates Origin, rejects invalid credentials, enforces its five-attempts/minute limit, and does not disclose secret configuration. A new login rotates the prior session; logout revokes the database token and clears the cookie.
4. Create the prepared product as a draft with its English name, aliases and an existing valid shelf. Verify it is hidden from public search until explicitly published. Publish it; then update its alias and shelf via the backoffice. The content update must return to draft, warn the maintainer, and hide it from public search until republished. Exercise the maintainer list/filter and cursor beyond 50 items to locate the record. After each publish, open a fresh anonymous shopper query; confirm the committed values and route appear without frontend redeployment, and all returned locations originate from stored shelf records.
5. Submit an invalid shelf, mismatched store/product identifier, empty required name and overlong alias through direct write requests as well as available form validation. Verify 422 `VALIDATION_FAILED` for invalid shelf/data, safe error text and unchanged row/aliases/version; unknown request fields must also be rejected. Attempt publishing an unmapped shelf and prove rejection. No browser import UI is required; operator import remains covered in TEST-0001.
6. Have sessions A and B load the same product version. Save A's shelf/alias edit, then save B's stale version. Submit the old expected_version and expect HTTP 409 conflict; preserve A's committed data, explain reload/review in B, and never silently overwrite. Reload B and confirm a deliberate new edit can succeed.
7. Archive the product (inactive for public lookup). Verify it is absent from public search and cannot receive a public route or Live-tool-backed spoken location via a stale/direct ID; the maintainer can still inspect/edit it. Republish and verify its location is searchable again. Retain the original public fixture for TEST-0001's frozen run.
8. Restart/revise the app container and repeat login/read plus a read of the newly committed product. Verify PostgreSQL preserves records independently of container files; session behavior follows the documented contract. Verify no source-project service or secret is required for the curated portal flow.
9. Compare all selected-copy files with their recorded hashes/source revision and verify license/attribution requirements have been resolved before distribution. Check no `.env`, keys, source databases, accounts, vendor/build artifacts or unrelated runtime services were copied. Record source read-only evidence; do not modify the source to make tests pass.

## Expected and pass/fail evidence
- Anonymous customer experience and protected maintainer experience share one hostname. Only a valid authorized server session with valid CSRF permits mutations; expired/logged-out/replayed sessions fail. Cookie lifetime matches the approved contract.
- Successful create/update/alias/shelf/draft/publish/archive changes persist and affect public lookup correctly. Invalid writes and stale versions cannot partially modify or overwrite valid data. Draft/archived products cannot leak through stale public IDs.
- Evidence: route/navigation captures, authorization matrix with redacted HTTP results, cookie-attribute checklist without values, CSRF denial records, version-conflict before/after snapshots, persistence comparison and reviewed reuse manifest. No credentials, raw audio or source user data in evidence.
- Any authorization bypass, secret leakage, invalid stored location, lost update or missing license decision blocks this gate. All results remain unmeasured until execution is authorized.
