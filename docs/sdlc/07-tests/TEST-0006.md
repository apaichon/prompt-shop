# Foundation and import integration gate

Proposed specification; no execution. This TASK-0001 gate depends only on foundation, importer and PostgreSQL, not downstream search, voice or UI.

## Setup
Use disposable PostgreSQL, approved migrations and the versioned 60-published-product/eight-aisle seed. Prepare valid new-product JSON, identical rerun, changed content under the same import version, and mixed valid/invalid-reference batches. Record fixture/schema hashes and baseline row counts.

## Steps
1. Apply migrations, seed once, and inspect database foreign keys, published-product counts and all entrance-to-shelf graph connections directly. Verify health/readiness and readiness failure without connection leakage.
2. Rerun identical seed/import; compare IDs, aliases and counts. Apply a new import version changing one product and verify its stored row/version. Same version with different content must be rejected.
3. Import batches whose later row references an invalid aisle/shelf, duplicate ID or invalid graph edge. Compare complete before/after rows and versions to prove transaction rollback and inspect row errors.
4. Restart the app container and query PostgreSQL directly to prove durable seed/import data. Confirm API contract fixtures are present for downstream work.

## Expected
At least 60 published products/eight aisles, no duplicate or invalid references, idempotent rerun, atomic rejection and durable records. Preserve migration/fixture hashes, SQL comparison output, importer errors and health/readiness results. No shopper search success is claimed by this gate.
