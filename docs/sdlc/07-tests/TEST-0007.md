# Catalog and routing API integration gate

Proposed specification; no execution. Isolated HTTP/database integration without frontend or speech services; not the deployed acceptance suite.

## Setup
Use migrated PostgreSQL with TEST-0006's valid seed and TEST-0001's frozen 30 prompts/expected IDs. Add isolated unknown, ambiguous, draft/archived and disconnected-map fixtures. Record schema/catalog/map hashes.

## Steps
1. Call POST /api/search for each frozen query; check at most three stored candidates, deterministic ordering, and at least 27/30 expected IDs in the first three. Check milk ambiguity, unknown/adversarial phrases and published-only filtering.
2. For every published seed product, call POST /api/routes from entrance. Compare source aisle/shelf labels, path endpoints and every edge against independently checked walkable geometry; no shelf crossing is allowed.
3. Exercise invalid origin, unknown/draft/archived ID, disconnected destination and unavailable database. Verify documented status/error codes and truthful location details, never invented paths or sensitive errors.
4. Import a new published item using the completed importer and verify API search sees it. Change map/catalog versions and verify consistent versions and fresh product location in API responses.

## Expected
Zero fabricated locations, all valid seeded paths connected, bounded candidates, documented failures and fresh committed data. Save HTTP assertions, per-query results, complete geometry validation and version comparisons. UI selection, accessibility, rendering and native Gemini Live conversation are separate later gates. The read-only search/route functions must also serve Live tools through their approved server adapters, without granting tool mutation rights.
