# ADK Live runtime, protocol and required-model smoke gate

Proposed specification; no execution. Mandatory Python ADK `Runner.run_live()` integration and one actual `gemini-3.8-live` exchange qualify TASK-0003 independently of the shopper UI. They do not establish the deployed 30-turn acceptance result.

## Setup
Use an ADK runtime/protocol harness with pinned package/configuration identities, `StreamingMode.BIDI`, AUDIO output and PCM16LE mono 16 kHz input/24 kHz output, synthetic English utterances and deterministic read-only catalog/route tools. Prepare multi-part events, async tool calls/cancellation, delayed generations, provider disconnect/quota, invalid frames and DB timeout. Record model/setup identity, origin, clock and tool facts; no secrets in fixtures. The [Live capabilities guide](https://ai.google.dev/gemini-api/docs/live-api/capabilities) documents PCM streaming and mixed event parts; implement the precise DES-0001 envelope contract.

## Steps
1. Create a session via POST `/api/voice/sessions` and upgrade WSS `/ws/voice` using its HttpOnly ticket. Verify exact Origin, 30-second single-use expiry and atomic consume across competing upgrades; no query-string credential. Wait for provider ready before streaming. Check session configuration names `gemini-3.8-live`, AUDIO output and only approved `classify_intent`, catalog and route tools. Reject accidental legacy setup options: unsupported thinking-level settings, disabled proactive audio or removed affective-dialogue fields. Classification runs for every completed semantic turn, including out_of_scope; classification, catalog and route declarations must explicitly use BLOCKING behavior; test cancellations even though model defaults may differ.
2. Stream 100 ms/3,200-byte input frames; check ≤6,400-byte frame cap, sample rate/endianness/channels, output 24 kHz playback, ≤16 KiB output frames and ≤1-second/48,000-byte output buffers. Induce slow-client overflow and require abort/flush/recovery rather than unbounded queues. Check microphone≤40KiB/s, burst≤64KiB, total≤10MiB/session and control frames≤4KiB/10 messages per second. Reject malformed/overlarge payloads. Process all simultaneous supported event parts and correlated control/tool fields, including interleaved audio and optional transcripts.
3. Exercise `search_catalog{query}` and `get_product_route{product_id,search_id}`. Require current-turn candidate membership; ambiguous search requires a later spoken turn or explicit selection. Assert no admin/write/arbitrary external tool access; the fixed authenticated Laya classifier is the only additional advisory intent tool. Enforce a 1.5-second catalog/route tool deadline (DB750ms); the separately qualified classifier uses1200ms, at most two searches plus one route call per turn, and candidate expiry after60s or a new search. Return typed failure for DB/tool timeout distinct from empty catalog results, preserving call IDs. Suppress location-response audio until the current tool sequence completes; pre-tool greetings/clarifications may stream but cannot invent shelf assertions.
4. Interrupt playback and cancel tools; verify old-generation audio queues clear, late/cancelled/duplicate responses cannot restart output or overwrite current facts, and tool cancellation is respected. Verify reconnect allocates a new session/generation without replaying earlier work.
5. Exercise setup30s/session300s-from-ready/idle60s limits, provider errors and explicit Stop. Silence, pings and provider chatter cannot extend user-activity idle timeout. Check ping20s/pong-grace10s transport cleanup. Confirm upstream/socket/context release and four-session/instance admission cap; log only safe metadata. Cloud Run360s is an outer bound, not session lifetime.
6. In an authorized provider environment perform an actual two-way native English conversation on `gemini-3.8-live`: spoken item → classify_intent contract → catalog tool → audible grounded answer, followed by spoken selection → classify_intent contract → route tool → grounded audible route. Compare every spoken location with tool facts and record provider/model evidence. A missing/unavailable required model leaves voice blocked; no transcription/synthesis or alternate-model substitution.

The isolated TASK-0003 gate may use a contract fixture for the separately owned Laya adapter so it does not depend on TASK-0010 completion. This must be clearly labelled and cannot satisfy REQ-0006 or integrated TEST-0002/0004; real Laya checkpoint qualification is TEST-0012.

## Mandatory ADK runtime evidence
1. Instrument the actual Python ADK `Runner.run_live()` path with content-free invocation/cleanup counters. Prove native audio and tools flow through this runtime on the real-model smoke, using pinned ADK/SDK versions and reviewed entrypoint evidence. Merely installing ADK, importing it, or bypassing it with a raw Gemini client does not pass.
2. Create simultaneous connections A/B with distinct in-memory ADK sessions and fresh `LiveRequestQueue` objects. Interleave synthetic utterances, tool results and close A; B must remain correct. Reconnect A with a new queue/session; no old close signal, caption, candidate, tool or audio can leak into either connection.
3. Stall provider consumption and inject a sustained stream. Enforce the queue wrapper pending PCM limit of one second/32,000 bytes plus bridge/output bounds and terminate with explicit recovery on overflow; rate limiting alone cannot establish bounded memory for ADK's queue. Test Stop, disconnect, expiry, provider exception and tool cancellation: always close the queue in finally, cancel and await the runner/stream tasks, delete the ADK session, revoke the Go session/turn capability and release capacity. Confirm counts return to baseline after repeated open/close cycles.
4. With `save_live_blob=false`, transient `InMemorySessionService`, no persistent artifact service, no memory plugins and no session resumption, inspect session/event/artifact stores after normal close and error cleanup. Remove final transcript/tool history from in-memory sessions and verify no audio/transcript persistence or body traces. Reconnect must create an empty conversation, not resume retained history.

The [ADK Live sessions documentation](https://adk.dev/live/sessions/) describes per-run queues and session history; these checks enforce this prototype's stricter transient-retention contract. Private bridge authorization follows DES-0001 and is checked below before runtime approval.

## Private bridge and tool-boundary checks
- Run the three-container contract: only Go on port8080 is public ingress; the separate Laya listener on8003 must also remain private. ADK listens on port8001 and exposes config/import-only `/healthz` plus authenticated `/live`; Go reaches it on127.0.0.1 with the Secret Manager bridge Authorization header. Verify a public browser cannot access the ADK listener or proxy arbitrary paths, and missing/wrong bridge credentials cannot open a live runner.
- For catalog/route operations, the authenticated ADK runtime calls only Go's private `http://127.0.0.1:8002/internal/tools/search_catalog` and `/internal/tools/get_product_route`. Accept only the Go-minted active session/turn capability supplied through trusted setup. Reject absent/forged/revoked capabilities, a capability from connectionA used for B, prior-turn replay, unknown tools, arbitrary caller URLs and admin/write requests. Verify rejected calls leave the database/UI unchanged.
- Race the two transports: delay/reorder `classification_completed` on the authenticated private bridge while releasing its HTTP catalog callback. Go must reject or hold the callback until it has accepted that trusted completion and returned its ACK; ADK must await the ACK before sending catalog HTTP callbacks. Replay an old attempt ID or inject model/client-authored completion metadata and verify rejection. Only the current session/turn/attempt completion permits the callback; no timeout can silently bypass this ordering.
- Kill the ADK bridge during audio and during an in-flight tool; Go must stop/flush the turn and offer explicit reconnect, not open a raw Gemini bypass. Verify ADK health has no Go/provider dependency cycle; readiness failures stay visible and do not leak bridge credentials.
- Inspect actual outgoing SDK setup, not just declared agent configuration: model must be `gemini-3.8-live`, native audio and BLOCKING tool declarations must survive ADK serialization, and prohibited legacy model fields must be absent. An ADK compatibility failure blocks the mandatory runtime gate.

Mock success cannot stand in for actual voice success; browser/VAD/end-to-end p95 remains TEST-0002.
