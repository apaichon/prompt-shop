# Customer portal Live-session fixture and accessibility gate

Proposed specification; no execution. Approved HTTP/WebSocket fixtures and browser audio stubs qualify TASK-0004 independently of live model APIs and TASK-0009 backoffice. This is not deployed voice acceptance.

## Setup
Serve the static SvelteKit shell with session-ticket/ready/audio/tool-result/interruption/error fixtures and read-only catalog/map responses. Stub PCM capture/playback, microphone permission and clock. Use 320/768/1280 CSS-pixel widths, keyboard and a declared screen-reader/browser pair.

## Steps
1. Exercise idle→Start voice→connecting→listening→thinking/tool lookup→speaking, plus spoken clarification/selection and Stop. Verify capture begins only after explicit Start/permission, VAD turn state is visible, and input/output transcript events visibly render as captions and never auto-trigger a separate search request.
2. Render factual cards/maps only from verified server tool-result events. Adapted Monti shopping interactions must connect candidate events to candidate highlights and route events to selected-product highlighting and map updates through explicit deterministic state transitions. Verify current search/candidate IDs and explicit selection for ambiguity; model text/audio alone cannot create shelf labels, inject HTML, trigger arbitrary actions or navigate to arbitrary URLs. Inject markup/action-shaped strings and unknown event types and verify escaped text or rejection. Fixture a tool timeout separately from true no-match and inspect different truthful UI states. Classifier timeout/busy/low-confidence abstention must show visible clarification/recovery and cannot create product IDs or update a shelf.
3. Simulate barge-in during buffered playback; clear queued audio and ignore stale generation/tool/card events. Require session_id, turn_id and generation_id to match active state; messages after Stop or from another session cannot change highlight, map, transcript or voice state. Feed mixed event parts and confirm none are dropped. Exercise mute/stop, output failure and reset without losing current verified location.
4. Show denied/unsupported capture, socket disconnect, ticket expiry, session300s expiry and idle60s close. Require explicit Restart voice/reconnect, stopped capture and usable typed search without reload; no old audio replay.
5. Verify stored labels, From entrance text, map/text equivalence and stale-map reload/retry. Verify spoken choice, keyboard/click choice and typed search all update the same controlled selection state; announce visible voice status and transcript captions without stealing keyboard focus. Complete keyboard search/selection/session controls with visible focus, accessible status announcements, 44px primary targets and no color-only directions.
6. Verify the adapted Monti desktop assistant panel/mobile drawer and product-action confirmation support only item selection/Show route. Closing the mobile drawer must end microphone capture/session, clear the active token before transport close, and restore focus to the launcher. Late background voice/ADK/Laya events must neither reopen it nor steal keyboard focus. Explicit typed submit or click selection may move focus to the corresponding result/route heading. Verify reduced-motion preference; no auto-start, cart, price, preference or identity actions survive reuse. Verify same-origin customer / and /backoffice shell/deep-link navigation against a placeholder route. Real maintainer auth/CRUD belongs to TEST-0005 after TASK-0009 and is not required here.

## Reference scope
The Monti source snapshot supplies patterns to adapt, not runtime evidence. Laya is mandatory for the integrated prototype. This bounded UI gate uses valid/abstained/error classification-event fixtures; actual checkpoint inference is TEST-0012 and real voice integration is TEST-0002/0004. Generated arbitrary UI is never accepted as a substitute for verified shopping events.

## Expected
Truthful accessible fixture states, correct event handling and no commerce/booking controls. Save component/browser assertions, playback-generation cancellation verdicts, state captures and accessibility checklist. Mock audio or fixture latency cannot count toward actual model/voice acceptance.
