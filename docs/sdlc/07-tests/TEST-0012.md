# Laya intent classification through ADK

Acceptance procedures are specified below; current partial execution and blockers are recorded in the TASK-0006 evidence section. This TASK-0010 gate uses actual Laya checkpoint inference through the ADK `classify_intent` tool in an isolated module harness. It does not depend on TASK-0003's complete voice transport. Full native-voice participation is independently required by TEST-0002 and TEST-0004 after both tasks integrate. Laya cannot be disabled or replaced to pass those gates.

## Setup
- Pin the English-root [convaiinnovations/laya checkpoint](https://huggingface.co/convaiinnovations/laya) to a real reviewed Hugging Face commit plus weight/tokenizer/config hashes at build; record runtime/dependencies and license provenance. No checkpoint revision is fabricated by this plan. Use real inference, not mocks or heuristic labels. Provisional CPU allocation is2vCPU/4GiB; record actual CPU/RAM settings, eager preload/warm-up and all cold/warm conditions.
- Freeze the 40 balanced English inputs below before holdout evaluation. Freeze confidence≥0.70 and top-two margin≥0.15 beforehand; these are provisional decision scores, not calibrated probability claims. Normal-set abstentions/errors count as wrong. Tuning after evaluation requires a clearly separated new holdout, never silent replacement of misses.
- Private service contract: port8003 POST `/classify`, authenticated `X-Internal-Token` known only to ADK/Laya; `{text}` with1–300characters; wrapper-owned intent-v1 labels. Response `{schema_version:"intent-v1",intent:string|null,confidence:number|null,margin:number|null,abstained:boolean,reason:null|low_confidence|timeout|busy|error,model_revision}`. Reject unknown fields, labels and inconsistent null/abstain/error combinations.
- Deadline1200ms includes queue wait≤200ms; one inference worker, at most four queued; no retries. Prepare wrong credentials, invalid text, malformed output, checkpoint failure, slow inference, overflow and cancelled sessions. Keep such fault cases separate from the 40 normal inputs.

## Steps
1. Invoke actual `classify_intent` against the pinned checkpoint for all40 inputs via the isolated ADK tool harness. Assert exact typed contract including nullable numeric confidence/margin and wrapper-owned schema, record expected/actual label, abstention/error and safe model/runtime identity. Verify threshold/margin configuration is frozen and real weights are loaded.
2. Compare confusion matrix and per-class accuracy; calculate overall correct/40 and non-abstained coverage. Require≥36/40 correct; abstentions/errors are misses. Test below-threshold/low-margin outputs, no-context ambiguous phrases and adversarial/malformed output separately; unknown labels and invalid shapes must return safe abstention/error, never IDs, locations or executable actions.
3. Test missing/incorrect internal token, public-port reachability, caller-supplied URLs/model/schema settings and attempts to call admin/write tools. Only the fixed authenticated endpoint is reachable from the approved runtime; no browser access, raw text logs or credential exposure.
4. Stall/saturate the worker and verify deadline1200ms, queue≤200ms, one active/four queued and no retry. Additional callers receive busy/abstain without unbounded work. A concurrent event-loop heartbeat/audio fixture must remain responsive. Cancel a turn while queued/running; its eventual result cannot enter a new turn, and queue/capability/session resources are cleaned up.
5. Measure cold checkpoint load and at least30 warm classifications separately; record raw timings, p50/p95/max, errors and actual CPU/RAM. Warm p95 must fit≤1200ms including queue, with observation29/30 as nearest-rank p95. No advertised33ms result counts as project evidence; load failure or missed budget remains a blocker.
6. Force each label using the isolated tool harness and verify advisory-only behavior: catalog lookup still checks published products; selections still require current candidate membership; repeat requests still require a valid selected route; out_of_scope cannot invoke payments/admin or writes. Labels never bypass authentication or generate shelf IDs.
7. Make Laya unavailable/disabled and verify explicit typed abstention, visible degraded-state/clarification event and usable recovery contract, with no successful-Laya result fabricated. Inspect all text/event/artifact/log stores after normal close, error and cancellation. Actual native model→ADK→Laya→catalog→voice/UI integration must classify every completed semantic turn, including out_of_scope and repeat requests, and is required later by TEST-0002/0004, not counted as passed from this isolated gate.
