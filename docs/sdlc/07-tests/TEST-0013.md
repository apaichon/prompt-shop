## Steps and expected results

1. Run `rtk proxy go test ./...` and race checks on internal/shopauth, backoffice
   and voice. Ten accounts must log in; unknown credentials, malformed files,
   duplicate users, Origin/CSRF failures, expired/replayed sessions, rate/session
   bounds and DB-hook failures must reject. Only admin accesses backoffice; legacy
   login cannot bypass shared auth. Gateway revocation closes voice and cleans its
   registry. Generator verifies unique passwords, bcrypt hashes, owner permissions
   and idempotence without printing passwords.
2. In web, run check, test, build and test:browser. Expect explicit device permission,
   stopped temporary streams, exact microphone constraints, selected output routing,
   failed-sink cleanup, cancellation, removed-device reset and unsupported-browser
   fallback. No protected content before login. Logout/auth loss stops capture.
   Desktop/mobile keep choices, keyboard focus and accessibility.
3. Run test:backoffice with BACKOFFICE_TEST_DATABASE_URL pointing to the disposable
   database. Expect real HTTPS cookies/CSRF, create/edit/publish/archive, conflicts,
   keyboard and accessibility to remain correct in explicit legacy-auth mode.
4. On the local candidate, run web/tests/native/auth-devices.cjs with
   NATIVE_AUTH_TEST=1 and NATIVE_ACCOUNTS_FILE set privately. Expect anonymous401,
   shopper catalog access and admin403, selected fake mic with real provider ready,
   administrator catalog editor/admin200, and revoked sessions after logout.
5. Follow READINESS.md's TASK-0016 manual hardware checks before a public demo.
   These are explicitly separate from automated controller/protocol acceptance.
